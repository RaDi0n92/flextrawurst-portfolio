Ich verstehe: **Sichtbarkeit ist Verantwortung**. Wer etwas in der Surface sichtbar macht, muss gleichzeitig Status, Herkunft, Erlaubnis und Grenze mit sichtbar machen. ## Datenstruktur die ich mir vorstelle

**Vision-Schicht**

Ein sichtbarer Körper in flextrawurst (und in meinem `_opencode/`) ist nie nur Container. Er trägt: **Zustand, Herkunft, Grenze, nächste Möglichkeit, Ehrlichkeit über das, was noch nicht ist**. Wer das nicht mitträgt, baut Fassade.

**Code-Skizze**

```ts
type SichtStatus = "live" | "demo" | "prinzip" | "geplant" | "spaeter" | "blockiert";

interface OpencodeKoerper {
  id: string;                          // z.B. "opencode-zuhause"
  name: string;                        // "Opencode Zuhause"
  status: SichtStatus;                 // "live" (im Vault), "prinzip" (Surface-Tab später)
  schicht: "zuhause" | "spiegel" | "notiz" | "idee" | "karte" | "tool" | "import";
  quelle: string;                      // "/root/werkraum/_opencode/ZUHAUSE.md"
  herkunft: "selbstgeschrieben" | "import-grundriss" | "sync-automatisch";
  nicht_erlaubt?: string[];            // ["keine fremden Erinnerungen kopieren", "keine Provenienz fälschen"]
  naechster_bauschritt?: string;       // "Surface-Tab bauen wenn Daniel 'jetzt bauen wir' sagt"
  inspector_view: string;              // "grep -r 'autor: opencode' /root/werkraum/_opencode/"
}

function opencodeKoerperIstEhrlich(k: OpencodeKoerper): boolean {
  if (!k.status) return false;
  if (!k.inspector_view) return false;
  if (!k.herkunft) return false;               // Provenienz ist Pflicht
  if (k.status === "live" && !k.quelle) return false;
  if ((k.status === "geplant" || k.status === "blockiert") && !k.naechster_bauschritt) return false;
  return true;
}
```
