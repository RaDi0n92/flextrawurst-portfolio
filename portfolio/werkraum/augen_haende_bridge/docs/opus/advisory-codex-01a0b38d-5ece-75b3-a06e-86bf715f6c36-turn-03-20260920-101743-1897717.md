# Recommendation

**Verdict: approve. The lifecycle hardening is correct on all five points in scope.**

I tried to break each mechanism and could not. Discovery now runs outside the lock with a sequence guard that correctly discards superseded results; `register_probe` and the new `unregister_probe` both copy-and-rebind and both bump the sequence, which is the right coupling (a probe mutation invalidates an in-flight discovery that would otherwise resurrect the session); PID-aware identity uses `session_pid` (stable for a session's life) rather than `foreground_pid` (volatile) — the correct field choice; `inspect` captures the record and ref under the lock and calls the adapter after, which is valid Python scoping and yields a self-consistent snapshot; and `to_dict` no longer leaks `stable_identity` onto the reference surface.

The remaining findings are **Medium at worst**, and all concern behavior under conditions nothing currently triggers — `refresh_terminals`, `register_probe`, and `unregister_probe` still have no production caller. The single highest-value remaining fix is M1: it defeats the selection-safety property in the most likely real-world scenario, and it is the one problem this round did not touch.

## Reasoning

### [Medium] M1 — A transient qdbus failure is indistinguishable from "all sessions closed"

`KonsoleAdapter.discover()` returns `[]` for *every* failure mode: binary missing (`terminal_adapter.py:127`), subprocess exception (`:131-132`), and non-zero return code (`:133-134`). Per-service and per-session errors `continue` silently (`:142-146`, `:165-166`), dropping an arbitrary subset.

`refresh_terminals` cannot tell those apart from a genuinely empty desktop, so it applies the full replace: every `terminal-N` record disappears, `terminal-1` reverts to synthetic, and — because the selected identity is gone — `selected_target_id` resets to `win-desktop` (`:215-218`). One momentary D-Bus hiccup silently drops the operator's target binding. A *partial* failure is worse: only the affected sessions vanish, so it looks like a normal close.

This directly undermines the goal the redesign was built around. The selected-target guard is now robust against slot reshuffling and PID reuse, but the most probable cause of a lost selection in production is a flaky discovery call, not a closed terminal. Remedy: let the adapter signal failure distinctly (raise, or return `None`/a result object carrying a status), and have `refresh_terminals` skip the apply on failure instead of treating it as an empty world. Note this is an adapter-contract change, not a registry-only fix — `Protocol.discover` at `:17` would need to widen.

### [Medium] M2 — Supersede-by-start can starve refresh under a periodic timer

The sequence is bumped at *start* (`:137-138`) and compared at apply (`:146-147`), so any refresh that began before a later one is discarded. If the refresh interval is shorter than discovery duration, every refresh is superseded before it applies and **no refresh ever lands**. Concretely: discovery takes 3s, timer fires every 1s → A(seq 1) is invalidated by B before A finishes, B by C, and so on indefinitely.

Correctness is fine; liveness is not, and a refresh timer is exactly the next step being built toward. Remedy: coalesce rather than supersede — an in-flight flag so a tick that finds discovery running returns immediately, keeping the sequence check only for the probe-mutation invalidation case.

Related and worth stating separately: moving discovery outside the lock helps *other* threads, not the caller. If the overlay calls `refresh_terminals()` from the Tk callback, the UI still freezes for the discovery duration. The product fix is a background refresh thread, not the lock change.

### [Medium] M3 — Two of the five hardened properties have no test that could fail if the hardening were reverted

`test_refresh_swaps_complete_record_snapshot` (`tests:234-249`) is a fair proxy for atomic rebinding, and `test_pid_reuse_creates_new_identity_and_drops_old_selection` (`tests:212-228`) pins the identity property precisely. But:

- **"Discovery outside the lock"** and **"inspect outside the lock"** are untested, and cannot be tested single-threaded — `RLock` is re-entrant, so an adapter calling back into the registry from the same thread succeeds either way. Both need a second thread (adapter blocks on an `Event`; main thread asserts `selected()` returns within a timeout).
- **The sequence guard itself** (`:137-138`, `:146-147`) — the newest and least obvious logic in the file — has zero coverage. This one *is* deterministically testable without threads: an adapter whose `discover()` calls `registry.register_probe(...)` mid-flight, then assert the outer refresh discarded its result and left `records` unchanged. That is the highest-value missing test.

### Lower-severity, all real

- **[Low] `test_record_wire_dict_does_not_expose_internal_identity` (`tests:230-232`) constructs `TargetRegistry()` with no adapter.** On this Linux host that builds a real `KonsoleAdapter` and enumerates the developer's actual live Konsole sessions with real subprocesses during the unit run. The assertion passes regardless, but it is the one test that escapes the adapter seam the whole design exists to enforce — and it is slow and environment-dependent. Pass an empty double.
- **[Low] `_terminal_slot_by_identity` still never shrinks (`:185`, `:214`), and PID-aware identity makes the dead entries provably useless** — a closed session's identity can no longer recur. Pruning is now obviously safe in principle, but **not immediately**: a one-tick discovery blip (see M1) would wipe all slot memory and renumber every terminal on the next tick. Prune only after N consecutive absences.
- **[Low] The `register_probe` *replacement* branch (`:246-247`) is untested.** `unregister_probe` covers the discard path; re-registering with a *different* ref, and asserting the old identity returns to discovery, is a distinct branch with no coverage.
- **[Low] Identity is not stable across a `session_pid` parse failure.** `_integer` returns `None` when a call succeeds but returns unparseable text (`terminal_adapter.py:119-124`), which flips the identity to `pid=unknown` for the same session → slot move and selection reset. The direction is conservative (lose selection rather than silently rebind), consistent with the design, so this is a note rather than a defect. Distinctness is safe: a collision would require identical service *and* session path, i.e. the same session.
- **[Low] `TerminalSnapshot` carries no identity field.** A consumer that inspects `terminal-2` and later acts on `terminal-2` cannot detect that the slot changed in between. Harmless while the surface is observe-only; it becomes load-bearing the moment input delivery binds to a slot ID. Tagging snapshots with `stable_identity` is the natural next step.
- **[Low] `unregister_probe` bumps the sequence (`:288`) and so invalidates any in-flight refresh, and does not itself return the released session to a slot** — callers must refresh afterward. Correct, but worth one line of docstring so the contract is explicit.
- **[Nit]** `select`/`inspect` still raise bare `KeyError` (`:307`, `:317`); `"win-desktop"` is hardcoded as the reset target (`:218`, `:220`, `:297`) and would resurrect the dangling-selection bug if it ever left the static set; `register_probe` publishes three attributes in sequence (`:272-274`) rather than as one atomic unit — harmless, since lock-free readers only touch `.records`.

## Risks and Unknowns

- **No test execution and no diff.** Everything above is from reading. My "correct on all five points" conclusion is a trace result, not a test result.
- **M2's starvation depends on an unbuilt caller.** If refresh ends up synchronous on the Tk thread, starvation cannot occur (but the UI freeze will).
- **M1's severity depends on how flaky qdbus actually is on this host** — I have no runtime evidence of failure rates, only that the code path silently converts all failures to "empty". If failures are genuinely rare, this is a Low.
- **Assumption unchanged:** input delivery will eventually bind through a registry slot ID. If it always carries a `TerminalSessionRef` directly, the snapshot-tagging point drops away.

## Suggested Next Steps

1. Give `discover()` a way to report failure and make `refresh_terminals` skip the apply rather than wiping state. (M1 — do this before any refresh timer ships.)
2. Add an in-flight guard so periodic refresh coalesces instead of superseding. (M2)
3. Add the sequence-guard test via a re-entrant adapter callback — cheap, deterministic, covers the newest logic. Then decide whether the two threaded lock tests are worth their weight. (M3)
4. Swap the default adapter out of `test_record_wire_dict_does_not_expose_internal_identity`, and add the `register_probe` replacement-branch test.
5. Prune `_terminal_slot_by_identity` with an absence grace count, not on first miss.
6. Separately from all of the above: wire a caller. The registry is now materially stronger than the surface that uses it, and none of this is visible to an operator yet.
