# Recommendation

**Verdict: approve with required follow-ups — not clean-merge, not a revert.**

Both headline goals are genuinely met: (1) a Windows client can construct `TargetRegistry()` with no qdbus/KDE execution, and (2) `refresh_terminals` does remove stale discovered sessions while preserving both the synthetic `terminal-1` fallback and the `terminal-probe` record. I traced both by hand and they hold.

But the fix is **locally correct and globally incomplete**. The stale-removal logic is built on positional target IDs (`terminal-{index}`), which means a "removed" stale session can silently hand its ID to a *different* live session. That directly contradicts the project's own stated identity rule in `contracts.py:44-46` ("A native window handle is not sufficient identity… instead of silently retaining a stale binding"). Today the surface is observe-only so the blast radius is a wrong label; the moment `send_probe`/`sendText` binds to a selected ID, it becomes a wrong-terminal input delivery. Additionally, **nothing in the shipped product calls `refresh_terminals()`** after construction, so the fix currently has no live effect.

## Reasoning

### (1) Windows instantiation — holds, with caveats

Verified by tracing, not by executing:

- `_default_terminal_adapter` (`target_registry.py:48-53`) returns `PlatformUnavailableAdapter` when `os.name == "nt"`; `discover()` returns `[]` (`:29-30`), so `refresh_terminals` makes zero adapter subprocess calls. ✔
- Import-time safety: the Windows client imports `augen_haende_bridge.target_registry`, which first executes the package `__init__.py`. I checked every module it pulls in — `probe_terminal` keeps `fcntl`/`pty`/`termios` inside the `PTY_WRAPPER` *string* (`probe_terminal.py:24-34`), and `socket.AF_UNIX` is only referenced inside methods (`:128`, `:132`). All other imports are stdlib. So package import does not explode on Windows. ✔
- The pattern matches existing house idiom (`windows_scanner.py:160`: `Win32WindowApi() if os.name == "nt" else None`), which is a point in its favor for consistency.

Two honest qualifications:

- **This is defense-in-depth, not the only guard.** Even the old path would not have spawned qdbus on Windows: `KonsoleAdapter.discover()` short-circuits on `shutil.which(self.command) is None` (`terminal_adapter.py:127`, `:102-103`). That lowers the *severity* of the bug being fixed, and it means the real value of this change is explicitness and intent, not a closed exploit. Worth saying plainly in the commit message rather than overclaiming.
- **`adapter or _default_terminal_adapter()`** (`:80`) uses truthiness where the invariant demands identity. A falsy adapter double (any object defining `__len__`/`__bool__`) would be silently swapped for a real `KonsoleAdapter`. For a "never run local KDE discovery" guarantee, `if adapter is not None` is the correct idiom.

### (2) refresh_terminals — holds; I tried to break it

Traced sequences:

- *Init → discover 1 ref*: static `terminal-1` (synthetic) registered, then overwritten by the real record; `_discovered_terminal_ids={"terminal-1"}`. ✔
- *Session closes → refresh with 0 refs*: pop `terminal-1`, clear set, `setdefault` restores the preserved frozen `_static_terminal_record`. ✔ (This is what `tests/test_terminal_adapter.py:72-99` covers.)
- *`register_probe` then refresh*: `terminal-probe` is never in `_discovered_terminal_ids`, so it survives. ✔ — but see the coverage gap below; this invariant is asserted only by a comment.
- Set-iteration/dict-pop ordering at `:123-125` is safe.

**Where it breaks — the multi-session counterexample.** IDs are assigned by enumeration position (`:130-131`). `discover()` sorts services *lexicographically* (`terminal_adapter.py:135-139`), and service names embed a PID (`org.kde.konsole-123`), so `org.kde.konsole-1000` sorts before `org.kde.konsole-99`. Consequences:

- Sessions S1→`terminal-1`, S2→`terminal-2`. S1 closes. Next refresh: `terminal-2` is removed and `terminal-1` now *is S2*. An operator who selected `terminal-1` (S1) is now bound to S2 with no signal whatsoever. "Stale removal" removed the wrong end.
- Even with **no** session closing, launching a new Konsole whose PID string sorts lower reshuffles every ID.

So the honest statement is: stale *records* are removed; stale *bindings* are not — they are silently rebound. That is precisely the failure mode `TargetScanItem.generation` exists to prevent elsewhere in this same codebase.

**Hidden coupling that constrains the obvious fix:** the positional IDs are load-bearing. `overlay_app.py:253` hardcodes `f"terminal-{index + 1}"` for its four panels, and `reference_surface.py:205` hardcodes `terminal-1..terminal-4` opacity keys. So you cannot simply switch to `terminal:{service}:{session_path}` without touching both surfaces. The workable shape is a stable identity (service+session_path, with a generation counter mirroring `windows_scanner._generation`) plus a separate display-slot mapping for the four fixed panels.

**Dangling selection:** `select()` validates membership (`:169-170`), but nothing revalidates after a refresh drops the selected ID. `selected()` (`:175`) and `inspect()` (`:178`) then raise a bare `KeyError` — notably, `inspect()` bypasses its own graceful "unavailable" snapshot path. The overlay happens to dodge this because it keeps its own `selected_target_id` copy and guards with `.get()` (`overlay_app.py:292`), but `TargetRegistry` is exported public API (`__init__.py:144`) and this is a latent crash for any other consumer.

**The fix has no live caller.** `refresh_terminals()` appears exactly twice outside its definition: the constructor (`:86`) and one test (`:96`). The overlay never refreshes, and `ReferenceRuntime.__init__` snapshots `registry.records` into a plain list once (`reference_surface.py:202-203`). So in the shipped observe-only surface, a Konsole session closed after startup still renders "real · available" forever. The correctness work is real; its user-visible effect today is zero. That gap belongs in the commit message, not discovered later.

### (3) Type / API regressions — minor only

- `TargetRegistry(adapter)` stays positional and backward-compatible; `Target(...)` positional construction matches `contracts.py:118-122` field order (`id, kind, label, host`) — I checked specifically for a silent label/host swap; there isn't one. ✔
- `PlatformUnavailableAdapter` structurally satisfies the `TerminalAdapter` Protocol (keyword-only `inspect`). ✔ The Protocol omits `available()`/`send_probe()`, which is fine: I grepped all call sites and nothing reaches through `registry.adapter` for those — `IsolatedProbeTerminal` holds its own adapter (`probe_terminal.py:105-121`).
- **Medium:** `PlatformUnavailableAdapter.inspect` returns `source="platform"` (`:35`), a fifth provenance value alongside `planned`/`synthetic`/`real` with no shared enum or constant. The overlay's coloring keys off `provenance.startswith("real")` (`overlay_app.py:261`), so it degrades gracefully — but the vocabulary is now undocumented and drifting. `error="platform_adapter_not_available"` also diverges in style from the registry's own `adapter_not_available` (`:192`).
- **Low:** this `inspect` is effectively unreachable — it only fires when `record.terminal_ref is not None`, which on Windows requires `register_probe` with a Linux ref. Acceptable as a defensive stub; just don't count it as covered behavior.
- **Low:** `PlatformUnavailableAdapter` and `_default_terminal_adapter` are absent from `__init__.py`/`__all__`, so the safety-critical platform-selection seam is private and tests reach into a private function. Given that this *is* the invariant you care about, it deserves a public, documented seam.
- **Nit:** `_default_terminal_adapter(platform_name)` compares against `os.name` semantics (`"nt"`). A caller passing `sys.platform` (`"win32"`) gets `KonsoleAdapter`. Harmless today only because `shutil.which` saves you — which is exactly the kind of accidental safety this fix was meant to replace with intent.

### (4) Missing tests — the largest gap

Ordered by what I'd actually require:

1. **High — the constructor wiring is untested.** `test_windows_default_does_not_construct_local_kde_adapter` (`:67-70`) exercises `_default_terminal_adapter("nt")` in isolation. Nothing asserts that `TargetRegistry()` *with no adapter argument* picks it up. Reordering `__init__`, or passing `sys.platform`, or the truthiness bug at `:80` would all pass this suite. Test the integration point: patch `target_registry.os.name` to `"nt"`, construct `TargetRegistry()`, assert the adapter type.
2. **High — no negative assertion that nothing is executed.** The strongest form of this invariant is behavioral: patch `subprocess.run` (and/or `shutil.which`) to raise, construct `TargetRegistry()` on a simulated `nt`, assert no raise. That is the test that actually encodes "the Windows client never owns KDE discovery."
3. **High — `register_probe` survival across refresh is asserted only by a comment** (`:121-122`). It has no caller anywhere in the repo and no test. Register a probe, refresh with zero refs, assert `terminal-probe` still present with `source == "real"`.
4. **High — no multi-session test.** Two refs → one ref, asserting which session each surviving ID points at. Written against the *desired* behavior it fails today; that is the point.
5. **Medium — no post-refresh selection test.** Select a discovered terminal, refresh it away, assert the defined behavior of `selected()`/`inspect()` (whatever you decide it should be — fallback vs. typed exception, but not an incidental `KeyError`).
6. **Low — test-double quality.** `test_refresh_removes_closed_discovered_sessions_but_keeps_static_fallback` builds refs via `type("Ref", (), {...})()` (`:75-83`) rather than a real `TerminalSessionRef`, so it cannot catch changes that depend on the dataclass contract; and `MutableAdapter.refs` is a class attribute later shadowed per-instance, which reads as accidental. Use the real frozen dataclass.
7. **Nit:** `test_registry_keeps_static_targets_and_marks_discovered_terminal_real` promises "keeps static targets" but asserts `terminal-1` has been *overwritten* to `real` (`:62-64`). The name misdescribes the assertion. Registry tests also sit in `test_terminal_adapter.py`; a `test_target_registry.py` would match the module split.

### Adjacent finding, outside your four scopes but in the same blast radius

**Medium — the Windows client can still fail to start before it ever reaches `TargetRegistry`.** `overlay_app.py:25` imports `BridgeRuntime` unconditionally → `transport_client.py:9` does `from websockets.asyncio.client import connect` at module level. `websockets` is an *optional* extra (`pyproject.toml:12-13`), and the README states the transport is opt-in and stays offline when `BRIDGE_URL`/`BRIDGE_TOKEN` are unset (`client_windows/README.md:32-40`). The PyInstaller bundle presumably vendors it, but the README's own "start natively on the VPS for layout and registry tests" path (`README.md:29-30`) breaks without the extra installed. If the theme of this change is "the client runs without platform-specific machinery," a lazy import inside `_start_optional_bridge` is the matching move.

## Risks and Unknowns

- **I did not diff against HEAD.** I cannot confirm which lines are new versus pre-existing, so some findings (e.g. positional IDs, the `or`-truthiness idiom) may predate this fix. That affects attribution, not validity.
- **I did not execute the test suite.** Every trace above is by reading. My claim that the two named goals hold is a code-reading result, not a test result — please confirm by running.
- **Unknown: intended lifetime of `terminal-1..4` as a UI contract.** If those four slots are a deliberate, permanent product concept ("four terminal panels"), the right fix is a stable-ID registry plus a slot-mapping layer, and my recommendation stands. If they were placeholder scaffolding, IDs can simply become opaque and the two hardcoded sites get rewritten. I can't tell from the code which it is, and it changes the shape of the fix substantially.
- **Unknown: concurrency.** `reference_surface` runs a `ThreadingHTTPServer`. Nothing calls `refresh_terminals` from a handler today, so there is no live race — but the pop-then-repopulate window at `:123-127` is not atomic, and the first background refresh timer you add will create one.
- **Assumption:** that input delivery (`send_probe`) is intended to bind to a `TargetRegistry`-selected target. `register_probe`'s existence and capture_method string (`:159`) point that way. If input will always go through a separately held `TerminalSessionRef` and never through a registry ID lookup, the identity finding drops from High to Medium.

## Suggested Next Steps

1. **Decide the identity model before anything binds input to these IDs.** Mirror `windows_scanner._generation` (`windows_scanner.py:169-175`): key discovered records on `(service, session_path)` with a generation counter, and keep a separate positional map for the four UI slots. This is the one item I would not ship input delivery without.
2. **Make selection survive refresh.** After repopulating, if `selected_target_id` is gone, define and implement explicit behavior — fall back to `win-desktop` and surface it in `status`, or raise a named `TargetGone` error. Silent `KeyError` from `selected()`/`inspect()` is the wrong answer either way.
3. **Add the two missing invariant tests** (items 1–3 above): constructor-level platform selection, the no-subprocess negative assertion, and probe survival across refresh. These are cheap and they encode exactly the claims this commit makes.
4. **Tighten two lines:** `adapter if adapter is not None else _default_terminal_adapter()` at `:80`, and give `source="platform"` a shared constant alongside `planned`/`synthetic`/`real`.
5. **State the scope honestly in the commit message:** that `refresh_terminals` currently has no caller outside `__init__`, and that `KonsoleAdapter.available()` already prevented qdbus execution on Windows, so this change is explicitness and defense-in-depth rather than a closed hole. Then decide separately whether the overlay should refresh on a timer — that, not this commit, is what makes stale removal visible to a user.
6. **Optional, adjacent:** make the `BridgeRuntime` import lazy in `overlay_app._start_optional_bridge` so the opt-in transport is genuinely opt-in at import time.
