# Recommendation

**Verdict: approve. No blockers, no high-severity findings.**

All seven areas in scope are correctly implemented. I traced the two-pass slot reservation, the probe dedup/migration path, and the selected-target guard against each test and against adversarial sequences the tests don't cover, and the logic holds — including the case that broke the previous version (a newly discovered session stealing a survivor's slot because it sorted earlier).

The residual findings are all **Medium or below, and all latent**: `refresh_terminals` and `register_probe` still have **no production caller** (grep: `target_registry.py:98` and tests only). That is what keeps three otherwise-serious issues — discovery I/O under lock, non-atomic `register_probe`, and PID-reusable identity — at Medium. Each becomes High the day someone wires a refresh timer or a probe lifecycle. Fix them before that wiring lands, not after.

## Reasoning

### What is genuinely correct (verified by trace, not by execution)

**Windows no-qdbus construction — sound.** `_default_terminal_adapter` (`:49-54`) → `PlatformUnavailableAdapter`; `adapter if adapter is not None else …` (`:89`) closes the truthiness hole. The new `test_windows_registry_constructor_never_spawns_kde_discovery` (`tests:75-90`) is a genuinely strong negative test: it patches both `shutil.which` *and* `subprocess.run` with `AssertionError` side effects, so it fails on any probe attempt, not just on the adapter type. That is the right shape for this invariant.

**Stable identity + slot decoupling — sound.** `stable_terminal_identity` (`:57-60`) removes the positional-ID failure entirely. Storing it on the record (`:70`) is what makes the selected-target check possible. Label derives from the slot, identity from D-Bus — the right split, and it preserves the `terminal-1..4` coupling in `overlay_app.py:253` and `reference_surface.py:205` without a rewrite.

**Two-pass reservation — sound.** I traced `test_new_session_cannot_steal_remembered_slot_from_survivor` (`tests:191-210`) plus a variant the test doesn't cover (new session appearing *after* the survivor in adapter order): pass 1 populates `used_slots` before any new assignment, so pass 2's `_next_available_slot` skips reserved slots regardless of iteration order. `_slot_is_available` correctly treats the restored synthetic `terminal-1` as claimable (`:222-225`), and `_next_available_slot` provably terminates. No ordering dependency survives.

**Atomic refresh — sound for refresh.** Building `new_records` off to the side and rebinding at `:201` means lock-free readers (`overlay_app.py:196`, `reference_surface.py:203`) see either the complete old or complete new dict. The comment at `:140-142` accurately describes what the code does. See M2 for where the promise stops.

**Selected-target safety — sound, and conservative in the right direction.** `:204-209` resets to `win-desktop` whenever the previously selected identity is gone *or* the slot now holds a different identity. I specifically tried to construct a silent-rebind: slot reshuffles caused by stale slot memory do occur (see M3), but the identity comparison catches every one of them. Losing a selection is the correct failure mode versus inheriting a stranger's terminal.

**Probe dedup/migration — sound and idempotent.** Traced `register_probe` (`:227-259`) for: same-ref re-registration (net no-op, `discard` then `add`), promotion of an already-discovered session (slot removed, synthetic restored, selection migrated to `terminal-probe` at `:257-258`), and the subsequent refresh (identity filtered at `:153`, so no duplicate). `test_probe_session_is_not_duplicated_by_standard_discovery` (`tests:150-168`) pins the important half of this.

### Findings

**[Medium] `self.adapter.discover()` runs inside the lock (`:138`).** On Linux that is one subprocess per service plus three per session, each with a 2s timeout (`terminal_adapter.py:94-100`). Every concurrent `targets()`/`select()`/`selected()`/`inspect()` blocks for the full discovery duration. `inspect()` has the same shape: it holds the lock across an adapter subprocess call (`:277-280`), so a slow inspect blocks a refresh and vice versa. Correctness is unaffected; liveness is. Remedy: hoist `discover()` above the `with`, and in `inspect()` resolve the record under the lock then call the adapter outside it. **Named tradeoff:** two concurrent refreshes could then land out of order and transiently resurrect a just-closed session — a monotonic refresh counter (discard results from a discovery started before the last applied refresh) closes that cleanly. Worth doing in the same change so the fix doesn't trade one latent bug for another.

**[Medium] `register_probe` mutates `self.records` in place while `refresh_terminals` swaps atomically (`:238`, `:241`, `:256`).** The atomicity guarantee is half-implemented. A lock-free reader iterating `registry.records.values()` (`overlay_app.py:196`) concurrently with `register_probe` can raise `RuntimeError: dictionary changed size during iteration`. Latent only because `register_probe` has no caller. Remedy: use the same copy-then-rebind idiom. This is an internal contradiction in the design, not just a missing lock — the module now states an invariant in a comment that one of its two mutators violates.

**[Medium] Identity is not generation-guarded; `service` embeds a reusable PID (`:60`).** `org.kde.konsole-<pid>|/Sessions/N` collides when the OS reuses a konsole PID *and* the session index repeats. Low probability, but the consequences are exactly what the redesign exists to prevent: (a) the new session inherits a dead one's slot (cosmetic); (b) if the dead identity sits in `_probe_identities`, the new unrelated session is **silently excluded from discovery permanently** (`:153-154`) — it never appears as a target at all; (c) the selected-target check would treat it as surviving, i.e. silent rebinding. The project already states the principle and ships the remedy in-house: `contracts.py:44-46` ("A native window handle is not sufficient identity. `generation` makes a reused handle a new target instead of silently retaining a stale binding") and `windows_scanner.py:169-175`. The guard is nearly free here — `ref.session_pid` is already captured; bump a generation when a known identity reappears with a different `session_pid` and fold it into the identity string.

**[Medium] No probe teardown path.** `_probe_identities` loses an entry only via `register_probe` with a *different* ref (`:231-232`). There is no `unregister_probe`. `probe_terminal.py:278` has `close()`, and it never touches the registry — so whoever wires the probe lifecycle must un-exclude the identity and drop the `terminal-probe` record, or that record stays `real · available` forever and its session stays invisible to discovery forever. Currently prospective (`register_probe` has no caller), which is exactly why now is the cheap time to add the symmetric method.

**[Low] Selection follows a *removed* session but not a *moved* one (`:204-209`).** When a surviving session legitimately changes slot, the operator is dropped to `win-desktop`. Safety is preserved, but the identity is verifiable and present — you could re-point `selected_target_id` to the session's new slot and fall back to `win-desktop` only when the identity is truly gone. Same safety, better human outcome. Preference, not a defect.

**[Low] Synthetic→real promotion of a selected slot is silent.** Static records carry `stable_identity = None`, so they take the `elif` branch (`:208`), which only resets on *absence*. An operator sitting on the `terminal-1` placeholder is silently bound to a live session when one is discovered into that slot. Benign direction (the reverse is correctly handled), and arguably the intended meaning of a placeholder — but it should be a documented decision, not an emergent one.

**[Low] `_terminal_slot_by_identity` never shrinks (`:203`).** Unbounded growth over a long-running overlay with session churn. Memory cost is trivial; the functional cost is M3(a). Prune identities unseen for N refreshes.

**[Low] `to_dict()` now emits `stable_identity` (`:81`), and it reaches the network.** `reference_surface.py:203, 211` serialize every record into HTTP state, so the konsole PID and D-Bus session path are now published on that surface. Not a credential, and the relay is loopback-only per `client_windows/README.md:41-42`, so impact is small — but `stable_identity` is an internal correlation key with no consumer need on the wire (`reference_surface.py:166-168` renders only `label`/`source`/`availability`). Dropping it from `to_dict()` is the conservative default. Nothing pins this schema in tests, so the change went in silently.

**[Low] `win-desktop` is a hardcoded fallback (`:207`, `:209`).** If it ever leaves the static set, `selected()` regains its dangling-`KeyError` failure. Derive it from `_register_static_targets` or assert it.

**[Nit] `select()` and `inspect(unknown_id)` still raise bare `KeyError` (`:268`, `:278`)** rather than a named error or the graceful unavailable snapshot. `overlay_app.py:292` guards with `.get()`, so no live crash.

### Test coverage

Materially improved — the constructor-wiring negative test, probe preservation, selection reset, survivor-slot retention, and anti-steal are all now pinned (`tests:75-210`). Remaining gaps, ordered:

1. **[Medium] Probe re-registration is untested.** `:231-232` (old identity leaves `_probe_identities` and becomes discoverable again) has no coverage. Register probe A, then probe B, then refresh; assert A reappears as a discovered terminal and B does not.
2. **[Medium] `TargetRecord.to_dict()` shape is unpinned.** A field was added that flows to an HTTP surface with nothing asserting the contract. One key-set assertion prevents silent schema drift.
3. **[Low] No atomicity assertion.** True concurrency is awkward to test deterministically; a cheap proxy is to hold a reference to `registry.records` across a refresh and assert the old snapshot is unmutated and `records is not old`.
4. **[Low] `PlatformUnavailableAdapter.inspect` (`:33-46`) is untested and unreachable** via the registry (it requires a `terminal_ref`, which Windows discovery never produces). Fine as a defensive stub — just don't count it as covered.
5. **[Low] No test for identity collision (M3) or synthetic→real promotion (the second Low).** Both would fail today if written against the desired behavior; that is the point of writing them.
6. **[Nit]** Every registry construction carries `# type: ignore[arg-type]` (`tests:106, 125, 142, 158, 181, 202, 220`) because the doubles don't satisfy the `TerminalAdapter` Protocol. Making them satisfy it would let mypy actually check the boundary the Protocol exists to define. Also, the registry now dominates a file named `test_terminal_adapter.py`.

## Risks and Unknowns

- **No `git diff` and no test execution.** Everything above is from reading the current files. My claim that the seven mechanisms are correct is a trace result, not a test result — run the suite to confirm.
- **The machinery is still inert.** `refresh_terminals` runs once in `__init__` and is never called again in production; `register_probe` has no caller at all. So slot stability, stale removal, and selection safety currently have zero user-visible effect. The overlay still shows a closed session as `real · available` indefinitely. This is the main honest caveat for the commit message.
- **Probability of M3 is genuinely low** (requires konsole PID reuse *and* a repeated `/Sessions/N`). I rate it Medium on consequence and in-house-remedy-cost, not on likelihood. Don't let me talk you into treating it as urgent.
- **Assumption:** input delivery will eventually bind through a registry-selected target ID. If input always flows through a separately held `TerminalSessionRef`, M3(c) drops to cosmetic.
