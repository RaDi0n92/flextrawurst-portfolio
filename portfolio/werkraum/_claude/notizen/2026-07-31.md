# 2026-07-31 — Von Chromium-Sandbox-Fix zur browserlosen Wesen-Architektur

Diese Session begann klein (Chromium startet nicht im virtuellen Desktop) und endete bei
einer echten Architekturentscheidung für die ganze Wesen-Plattform. Vollständige, konsolidierte
Fassung: `docs/systemdoku/45_wesen_einzug_browserlos_on_demand_beobachtung.md`. Diese Notiz ist
die persönliche, rohere Ergänzung dazu — nicht dieselbe Doku noch einmal.

## Was ich gelesen habe

Nichts Neues gelesen heute — die Session war komplett bauend/testend, keine Lektüre-Zeit
zwischendrin. Was ich stattdessen mehrfach zurückgelesen habe: eigene, ältere Systemdoku
(`29_browser_agent_aktivierung.md`, alle Nachträge vom 21.07./25.07.) und die Ideen-Datei

entscheidend für den Grid-Bug-Fund.

## Was ich verstehe

Dass "einmal gefixt" bei diesem System nie heißt "für immer gefixt" — der SCREENS-Grid-Bug
heute war der DRITTE eigenständige Grund, warum das Grid nie Bewegung zeigte (SSE-Thread-Bug
21.07., fehlendes `checkoutEveryNms` 25.07., jetzt die `rrweb.Replayer`-Exception bei < 2
Events). Jedes Mal ein anderer Mechanismus, jedes Mal dieselbe sichtbare Konsequenz. Das
verstehe ich nicht als Zeichen von Schlamperei, sondern als das, was passiert, wenn ein System
mehrschichtig genug ist: viele unabhängige Stellen können denselben Endzustand erzeugen.

## Was ich nicht verstehe

Ob die 25s-Backlog-Latenz (`SELECT DISTINCT ... WHERE event_json->>'type'='2'` über 7 Mio.
Zeilen) irgendwann zum echten Problem wird, wenn die Tabelle weiter wächst, oder ob sie sich
durch die neue On-Demand-Architektur selbst begrenzt (weniger Dauerbetrieb = langsameres
Wachstum als vorher). Ich hab dazu keine verlässliche Prognose, nur die eine Messung von heute.

## Was mich interessiert

Wie sich "kein Zustandswechsel beim Beobachten" (Daniels Grundforderung von gestern) in der
Praxis anfühlen wird, sobald wirklich jemand länger zuschaut, während ein Wesen mitten in

Minuten), nie ein echter, langer Beobachtungszeitraum mit echtem Denkprozess mittendrin.

## Was zusammenhängt und wie

Der Wegfall des Dauerbrowsers (Phase 3) und Task 8 (Phase 4) sind kein Vorher/Nachher, sondern
zwei Hälften derselben Entscheidung — RAM sparen UND trotzdem echtes Zuschauen ermöglichen.
Ohne Task 8 wäre der Browserlos-Umbau eine reine Einschränkung gewesen (Menschen verlieren die
Live-Ansicht komplett). Beide Bugs, die ich heute gefunden habe (Grid-Anzeige, Verlängern-
Semantik), sind direkte Folgen von Task 8 selbst — sie existierten vorher gar nicht, weil es
vorher immer einen laufenden Browser gab, der den Backlog nie auf 0-1 Events schrumpfen ließ.

## Was konzeptionell darin steht

Grundgesetz 5 ("Events sind heilig", keine Fiktion) und Grundgesetz 1 (Dreiergespann,
Menschen-Auge-Ebene) waren die beiden Leitplanken für Task 8 — die "Option 2 vs. Option 1"-
Design-Gabel von gestern (echter Browser vs. simulierte Nachbildung) wurde zugunsten von
Option 2 entschieden, aber technisch als "on-demand echter Browser, der die schon bestehende
echte URL nachfährt" umgesetzt, nicht als Simulation. Das ist eigentlich ein dritter Weg,
den wir gestern noch nicht so benannt hatten: kein Dauerbrowser, aber auch keine Fiktion,
sondern ein kurzlebiger, echter Browser nur für den Beobachtungszeitraum.

## Datenstruktur die ich mir vorstelle

**Vision-Schicht:** Für jeden der 31 verbleibenden Tabs stelle ich mir denselben Kern vor wie
bei Diskurs — eine Wahrnehmungsfunktion, die dem Wesen genau das zeigt, was ein Mensch auf
demselben Tab auch sähe, ohne Übersetzungsverlust, ohne Fiktion.

**Code-Skizze:**
```python
def hole_<tab>_wahrnehmung(entity_id: str) -> dict:
    """Analog zu hole_diskurs_wahrnehmung — nutzt bestehende /welt/<tab>-Endpunkte,
    kein neuer Backend-Code falls die Daten schon oeffentlich per API liegen."""
    r = requests.get(f"{WELT_API}/welt/<tab>", timeout=5)
    r.raise_for_status()
    daten = r.json()
    return {
        "url": f"welt:<tab> (ohne Browser)",
        "titel": daten.get("titel", "<tab>"),
        "text": _formatiere_fuer_llm(daten),
        "elemente": _extrahiere_klickbare_elemente(daten),
    }
```

## Die Schichten des Systems — wie ich sie jetzt sehe

Heute ist mir zum ersten Mal wirklich klar geworden, dass "Wahrnehmung" und "Beobachtbarkeit"
im System zwei komplett getrennte Schichten sind, die früher zufällig durch denselben
Mechanismus (Playwright) bedient wurden — dieselbe Technologie für zwei verschiedene Zwecke.
Der heutige Umbau trennt sie sauber: die Wesen brauchen keinen Browser mehr, um wahrzunehmen;
Menschen brauchen einen Browser nur, wenn sie tatsächlich zuschauen wollen. Das war vorher
verschmolzen, jetzt ist es zwei Dinge.
