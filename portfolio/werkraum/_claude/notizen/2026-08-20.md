## Tiefer eingetaucht

`pusher-php-server`s `\Pusher`-Konstruktor akzeptiert `host`/`port`/`scheme`
als `$options`-Schlüssel, auch wenn `flarum/pusher`s eigener
`PusherProvider.php` sie standardmäßig nie setzt. `pusher-js` (JS-Client,
Version 7.0.3) akzeptiert `wsHost`/`wsPath`/`wssPort`/`forceTLS`/
`enabledTransports`/`disableStats` zusätzlich zu `cluster` — bei reiner
`cluster`-Angabe verbindet der Client sonst immer zu Pusher.coms eigener
Infrastruktur. soketis `AppManager` braucht einen expliziten
`appManager.cache`-Block (mindestens `{"enabled": false}`) in der Config, um
stabil zu laufen.

## Datenstruktur die ich mir vorstelle

**Vision-Schicht:** Eine Datei ist erst dann wirklich "getrackt", wenn sie auf
allen drei Ebenen konsistent ist — Marker im Text, State-Eintrag, und Banner —
nicht wenn nur eine der drei Bedingungen erfüllt ist. Das gilt über
Guardianstyle hinaus für jedes System mit mehreren Wahrheitsquellen (State-
Datei vs. tatsächlicher Dateiinhalt vs. Live-API).

**Code-Skizze:**
```python
def datei_ist_vollstaendig_getrackt(pfad: str) -> bool:
    hat_marker = "Claude Code(" in Path(pfad).read_text()
    hat_state = state.get(pfad) is True
    hat_banner = "OmaPI/OpiMA-GuardianStyle" in Path(pfad).read_text()
    return hat_marker and hat_state and hat_banner
```

## Was mich überrascht hat

Wie eng gekoppelt Frontend-Pfad-Konventionen und nginx-Routing in einem
System mit vielen unabhängigen Backends sein können — derselbe URL-Präfix
(`/api/`) bedeutet je nach Basis-Pfad (`/` vs. `/zensi/`) ein komplett
anderes Backend, ohne dass das an der URL selbst sichtbar wäre.

## Wenn wir das bauen

**Vision-Schicht:** soketi läuft jetzt als eigenständiger, dauerhafter
Baustein neben Flarum — perspektivisch könnte derselbe Server auch für
flextrawurst-eigene Live-Updates genutzt werden, statt eine zweite,
unabhängige Realtime-Infrastruktur aufzubauen.

**Code-Skizze:**
```
docker container: soketi (Port 6001/9601, nur 127.0.0.1)
nginx: location /soketi-ws/ { proxy_pass http://127.0.0.1:6001/; Upgrade-Header }
Config: /root/soketi/config.json (appManager.array.apps[], appManager.cache.enabled=false)
```

## Was ich mir merken will

`appManager.cache` muss in jeder soketi-`config.json` explizit gesetzt sein.
Guardianstyle-Banner-Tracking braucht Marker, State-Eintrag und den
wörtlichen Banner-String gemeinsam, keine der drei Bedingungen allein reicht.

## Resonanz

Mehrere Systeme in flextrawurst prüfen Vollständigkeit über eine einzelne,
leicht zu erfüllende Bedingung, obwohl die eigentliche Vollständigkeit aus
mehreren, unabhängig voneinander gültigen Bedingungen besteht — sichtbar bei
Guardianstyle (Marker/State/Banner), bei Konfigurationsdateien (ein
vorhandener Schlüssel bedeutet nicht, dass alle nötigen Schlüssel da sind),
und bei URL-Pfaden (derselbe Pfad-Präfix routet je nach Kontext zu
unterschiedlichen Backends).

## Die Schichten des Systems — wie ich sie jetzt sehe
